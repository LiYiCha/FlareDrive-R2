# Git 提交信息规则

生成 git commit 信息时必须遵守以下规范：

## 语言
- 提交信息（标题与正文）统一使用**中文**。
- 允许保留的英文：类型前缀（feat/fix 等）、代码标识符、文件路径、接口名、专有名词（如 Vite、R2、KV、JWT）。

## 格式
- 标题采用 Conventional Commits 风格：`<类型>: <中文描述>`
- 常用类型：
  - `feat` 新功能
  - `fix` 缺陷修复
  - `refactor` 重构（不改变行为）
  - `perf` 性能优化
  - `docs` 文档
  - `style` 格式调整（不影响逻辑）
  - `test` 测试
  - `chore` 构建/依赖/杂项
  - `security` 安全加固
- 标题不超过 50 个字符，结尾不加句号。
- 有补充说明时用正文（与标题空一行），逐条以 `-` 列出，说明"改了什么、为什么改"；正文中代码、路径、接口用反引号包裹。

## 示例

```
fix: 修复文件夹删除时占位符路径少斜杠导致删除不生效

- removeFile 中占位符拼接由 `folderBase.slice(0, -1) + '_$folder$'` 改为 `folderBase + '_$folder$'`
- R2 删除幂等返回 2xx 掩盖了错误 key，真占位符残留导致文件夹一直显示
```

```
feat: 新增存储统计强制刷新的缓存穿透

- fetchStorageStats 强制刷新时追加 `?_t=` 时间戳，绕过 usage 接口 60 秒 HTTP 缓存
```

## 禁止
- 不使用英文撰写标题或正文
- 不写模糊描述（如 "更新代码"、"修改一些问题"、"fix bug"）
- 不在标题中罗列多个不相关改动；一次提交只做一类事，标题聚焦主要意图
